# Platform Audit Logs Gap Register

## Verified Contract Matrix

| Field/capability | Source | Status |
| --- | --- | --- |
| Actor user ID/type | `PlatformAuditLog` written by `SuperAdminService` | Implemented |
| Actor tenant ID | Authenticated `SuperAdminActor` | Implemented |
| Action/resource/resource ID | Backend mutation service arguments and stable domain action names | Implemented |
| Target tenant ID | Backend-resolved platform mutation target | Implemented |
| Request/correlation ID | Existing `requestContext` | Implemented |
| Outcome/timestamp | Backend defaults | Implemented |
| Metadata | Minimal transition/reason/plan identifiers | Implemented |

| Tenant audit list | `GET /audit-logs` | Existing tenant scope only |

## Confirmed Gaps

### ARCHITECTURE GAP

- Platform audit records are written after existing super-admin mutations/outbox publication rather than inside one shared transaction for every mutation. A future refactor should make mutation, outbox, and audit persistence atomic where required.

### OPERATIONAL GAP

- No retention, archive, export, or external immutable/WORM storage policy is defined for platform audit records.
- Actor display names/emails are not joined into the platform response; the UI shows authoritative actor IDs only.

### BACKEND CONTRACT GAP

- No date-range filtering, cursor pagination, or bulk export contract exists.
- Read access itself is not audited; ordinary audit-log viewing remains intentionally read-only and unaudited.

### FRONTEND GAP

- Platform audit UI supports only backend-provided action/resource filters and pagination. No client-side filtering or mutation controls are provided.

### REALTIME INFRASTRUCTURE GAP

- Platform audit records are request-time query data; no realtime audit stream is exposed.

### TEST INFRASTRUCTURE GAP

- No dedicated platform audit HTTP E2E suite or frontend component test runner is configured.

## Scope and Security

- `AuditLog` remains tenant-scoped and is not queried by `/platform/audit-logs`.
- `PlatformAuditLog` is global, append-only, guarded by `super-admin.read`, and never accepts actor identity or platform scope from the browser.
- PostgreSQL triggers reject updates and deletes for platform audit records.
- Metadata is generated by backend-controlled platform mutations; raw requests, tokens, credentials, and full database snapshots are not stored.
