# Gap Closure Master Register

## Scope and audit method

This register consolidates current repository evidence from module gap registers, platform contracts, security, data-integrity, operational, deployment, and test reviews. Update it alongside implementation changes.

It is the source of truth for implemented contracts and remaining gaps; a "Resolved with Gap" status means the scoped defect is fixed while explicitly listed release evidence or adjacent product contracts remain outstanding.

## Tenant base currency contract

- Status: implemented and verified for tenant sales and purchasing.
- Each tenant configures one ISO 4217 base currency before creating new sales orders or purchase orders. New orders snapshot that currency; historical records remain nullable for backward compatibility.
- Initial currency setup remains possible for legacy tenants whose transactions have no currency snapshot; those historical records are never backfilled. Later currency changes are rejected when sales-order, purchase-order, or payment history exists. Database row locks serialize configuration changes against new sales-order and purchase-order creation.
- Tenant settings UI and sales-order, payment, and purchase-order totals use the recorded currency where available.
- Scope boundary: platform subscriptions/invoices, foreign-exchange conversion, and mixed-currency transactions are not included. Inventory valuation currency conversion and opening-cost reconstruction are separate concerns.
- Validation: currency migration deployed to `cafe_os_test`; focused sales-order and purchase-order integration suites passed 2 suites / 17 tests, and DTO validation passed 2 tests. The latest full API validation passed 102 unit suites / 452 tests, 24 integration suites / 130 tests, and 7 E2E suites / 23 tests. Monorepo build, lint, and typecheck passed; Turbo's optional OpenTelemetry workspace warning remains non-blocking.

## Latest Module Update (2026-10-24): Configurable Inventory Reordering

- Tenant-scoped `GET /inventory/items/:inventoryItemId/availability` reports available, reserved, and on-hand quantities per location and in totals from one repeatable-read snapshot. It also returns reorder alerts and suggestions.

Rules can use tenant-total or per-warehouse scope, trigger on `available <= reorderPoint`, and select target-stock or fixed-quantity suggestions with alert-only or alert-and-suggest actions.
